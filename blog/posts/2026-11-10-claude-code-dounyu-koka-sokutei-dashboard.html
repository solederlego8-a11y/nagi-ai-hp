Claude Code の導入効果は何で測る？管理者ダッシュボードで見える指標と見えない指標

更新日：2026年11月10日｜執筆：凪AI（運営：フォローズ）編集部

Claude Codeを導入して数か月たつと、経営層から「効果はあったのか」と聞かれます。このとき、管理者が使える画面は契約の種類によって違い、見えない指標もあります。この記事では、Anthropic公式ドキュメント「Track team usage with analytics」と「Monitoring with OpenTelemetry」（確認日：2026-11-10）に書かれている内容だけを使い、契約ごとに「何が見えるか・見えないか」を1つの表にまとめます。

30秒で判断
  • Teams・Enterpriseは、管理画面のダッシュボードで、利用者数・セッション数・承認された行数が見える。PR（プルリクエスト）数などの貢献指標は、GitHub連携の追加設定が必要
  • Claude Console（API）は、利用者数・支出・承認された行数が見える。GitHub連携による貢献指標は、公式の記載上、現時点では対象外
  • Bedrock等のクラウド経由は、Anthropic側のダッシュボードの対象外。OpenTelemetryで自社の監視基盤に送る必要がある

関連：料金の管理は利用料金の上限と管理、考え方は業務自動化のROIの測り方

管理者は、Claude Codeの利用状況をどこで見られますか？

公式ドキュメント（確認日：2026-11-10）では、Claude Code用の分析画面が2種類あります。Claude for Teams・Enterpriseの契約は「claude.ai/analytics/claude-code」、API（Claude Console）の契約は「platform.claude.com/claude-code」です。Teams・Enterpriseの画面は、管理者（Admin）とオーナー（Owner）が見られます。Claude Consoleの画面は、閲覧権限（UsageView）が必要で、Developer・Billing・Admin・Owner・Primary Ownerの各ロールが持っています。

Amazon Bedrock、Google Cloud、Microsoft Foundry経由の場合、公式は、Claude Codeがこれらのクラウドの利用状況をAnthropicに送らないため、分析画面とAnalytics APIの対象外と説明しています。次の表は、契約ごとの違いです。

契約の種類見える指標見えない（対象外の）もの追加の取得手段
Teams・Enterprise承認された行数、提案の承認率、日次の利用者数とセッション数、利用者ランキング、CSV出力貢献指標（PR数など）は、GitHub連携を設定するまで見えない。ZDR（ゼロデータ保持）の組織は貢献指標が使えない支出レポート（CSV）。Enterpriseは「Enterprise Analytics API」（Teamsでは使えない）
Claude Console（API）承認された行数、提案の承認率、利用者数、セッション数、支出（日次）、メンバー別の支出と承認行数GitHub連携による貢献指標。支出は分析用の推定値で、実際の費用はCostページで確認するClaude Code Analytics API（Admin APIキーが必要）
Bedrock・Google Cloud・FoundryAnthropic側の分析画面では見えない分析画面・Analytics APIの全指標OpenTelemetry、またはゲートウェイ

出典：Anthropic「Track team usage with analytics」（code.claude.com/docs/en/analytics）、「Manage costs effectively」（code.claude.com/docs/en/costs）、確認日 2026-11-10。画面や機能は変更される可能性があるため、利用前に公式ページで再確認してください。

貢献指標（PR数など）を見るには、何が必要ですか？

貢献指標（contribution metrics）とは、公式ドキュメントでは、Claude Codeの支援を受けて提出されたPR数やコード行数を、GitHub連携によって集計する指標を指します。公開ベータ版の機能として案内されており、Claude for TeamsとEnterpriseで使えます（確認日：2026-11-10）。設定には、次の4つの手順と条件があります。

  1. GitHubの管理者が、組織のGitHubアカウントにClaude GitHubアプリ（github.com/apps/claude）をインストールする
  2. Claudeのオーナーが、管理設定のClaude Codeのページ（claude.ai/admin-settings/claude-code）で、Claude Codeの分析機能をオンにする
  3. 同じページで「GitHub analytics」のトグルをオンにする
  4. GitHubの認証を完了し、集計対象のGitHub組織を選ぶ

設定にはオーナーのロールが必要です。データは、有効化から通常24時間以内に表示されます。次の条件にも注意が必要です。

  • 集計対象は、github.com上のリポジトリ。GitHub Enterprise Serverのリポジトリは、利用状況の指標のみで、貢献指標は出ない
  • 集計対象は、claude.aiの組織内のユーザーのみ。Claude Console（API）やサードパーティ経由の利用は含まれない
  • ゼロデータ保持（ZDR）が有効な組織では、貢献指標が使えず、利用状況の指標のみ表示される

つまり、自社が社内でGitHub Enterprise Serverを使っている場合や、API契約で使っている場合は、PR数による効果測定が、公式の画面では取れません。その場合は、既存の開発管理の数字（後述）と組み合わせる必要があります。ZDRについては入力データの学習と保持期間で整理しています。

OpenTelemetryでは、何が測れて、何が含まれませんか？

OpenTelemetry（オープンテレメトリ）とは、アプリの利用状況を、標準の形式で自社の監視基盤へ送る仕組みです。Claude Codeは、公式ドキュメント（確認日：2026-11-10）によると、環境変数「CLAUDE_CODE_ENABLE_TELEMETRY=1」で有効にします。自社の明示的な設定が必要な選択式の機能で、送り先は自社が設定した窓口のみです。どの契約でも使え、公式は、利用者別のトークン数と費用の指標を、ほぼリアルタイムで自社の監視基盤に流せる、唯一の方法としています。

指標（公式の名称）測れる内容
claude_code.session.count開始したセッション数
claude_code.token.usage使用したトークン数（利用者・チーム・モデル別に分解可能）
claude_code.cost.usageセッションの費用（近似値）
claude_code.lines_of_code.count変更されたコード行数
claude_code.commit.count / pull_request.count作成されたコミット数、PR数
claude_code.active_time.total稼働時間（秒）

プライバシーに関する公式の記載は、次のとおりです。ファイルの中身やコードの断片は、指標にもイベントにも含まれません。プロンプトの内容は既定では収集されず、長さのみが記録されます。内容を含めるには、「OTEL_LOG_USER_PROMPTS=1」を設定する必要があります。また、OAuth認証の場合、メールアドレス（user.email）が計測データの属性に含まれ、自社が設定した送り先にのみ送られます。社内で従業員の利用を測る場合は、このメールアドレスの扱いを、法務や人事と事前に確認してください。

費用の指標は、公式が「近似値であり、正式な請求データは別に確認する」と注記しています。設定は、管理者が配る設定ファイル（managed settings）に入れて、全員に一括で適用できます。

どの数字を「導入効果」として使えますか？

公式ドキュメントは、貢献指標の使い方として、導入が進むにつれて利用者1人あたりのPR数がどう変わるかを追うこと、そして、DORA指標やスプリントの速度など、すでに使っている開発の指標と併用することを案内しています。この記事の観点からは、使える数字は3つの層に分けられます。

測りたいこと使える数字この数字だけでは言えないこと
使われているか（定着）日次の利用者数、セッション数、利用者ランキング業務の成果が上がったかどうかは分からない
どれだけ使ったか（コスト）トークン数、費用の推定値、利用者別の支出費用に見合う成果が出たかどうかは分からない
成果につながったか（効果）PR数・コミット数の推移、自社で既に測っている開発指標（DORA指標、スプリント速度など）Claude Code以外の要因（人員、案件の難しさ）の影響は分けられない

なお、「承認された行数」は、公式の定義では、Claude Codeの編集ツールが追加または削除した行のうち、利用者が承認したものの合計で、却下された提案は含まれず、後から削除された行も合計から引かれません。行数が多いほど成果が大きい、とは限らないため、この数字だけで効果を判断しない運用が安全です（これは公式の記載ではなく、当社の見解です）。

導入前の数字（基準値）がなければ、導入後の変化は説明できません。試行の開始前に、既存の指標を記録しておくことが重要です。試行の設計はPoCの成功基準の決め方で整理しています。

どの契約なら、どの測り方を選べばよいですか？

契約の種類と、自社の開発環境の組み合わせで、選ぶ測り方が変わります。次の表は、判断の起点として使えます。

自社の状況最初に使う測り方補う手段
Teams・Enterpriseで、GitHub（github.com）を使っている管理画面のダッシュボード（利用状況＋貢献指標）支出レポート（CSV）で費用を確認
Teams・Enterpriseで、GitHub Enterprise Serverを使っている、またはZDRが有効管理画面のダッシュボード（利用状況のみ）OpenTelemetryでコミット数・PR数を取得
Claude Console（API）Consoleのダッシュボード（利用者数・支出・承認行数）Analytics API、OpenTelemetry
Bedrock・Google Cloud・FoundryOpenTelemetry（自社の監視基盤）クラウドの請求コンソール（費用）

表のうち、「OpenTelemetryでコミット数・PR数を取得」は、公式の指標一覧にコミット数とPR数の指標があることからの整理です。自社のGitHub Enterprise Server環境で期待どおりに数字が出るかは、記事執筆時点では確認していません。試行の段階で必ず確認してください。

費用と効果を、セットで説明したい場合
  • 費用の上限・見る場所：利用料金の上限と管理
  • 試行後に社内展開する判断：社内展開の手順
  • 稟議書に効果の根拠を書く：稟議書の書き方

よくある質問

Q. Claude Codeの導入効果は、どこで確認できますか

Teams・Enterpriseは claude.ai/analytics/claude-code、Claude Console（API）は platform.claude.com/claude-code のダッシュボードで確認できます。クラウド経由の場合は、OpenTelemetryで自社の監視基盤に送る必要があります。公式ドキュメント（確認日：2026-11-10）の記載です。

Q. PR数やコミット数は、すべての契約で見られますか

見られません。管理画面の貢献指標は、Teams・Enterpriseで、GitHub連携を設定した場合のみです。API契約は対象外で、GitHub Enterprise ServerとZDRの組織では、貢献指標が出ません。

Q. OpenTelemetryで、従業員のプロンプトの内容は見えますか

既定では見えません。プロンプトの内容は収集されず、長さのみが記録されます。環境変数「OTEL_LOG_USER_PROMPTS=1」を設定した場合のみ、内容が含まれます。導入する場合は、社内の同意と規程を先に整えてください。

Q. 承認された行数が多ければ、効果が大きいと言えますか

言えるとは限りません。承認された行数は、利用者が承認した編集の行数の合計で、品質や成果を直接示す数字ではありません。導入前の基準値や、既存の開発指標と組み合わせて判断してください。

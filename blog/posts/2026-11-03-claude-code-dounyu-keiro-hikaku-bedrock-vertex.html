Claude Code の導入経路比較｜Teams・Enterprise・Bedrock・Google Cloud・Foundry

更新日：2026年11月3日｜執筆：凪AI（運営：フォローズ）編集部

Claude Codeを会社で使うとき、Anthropicと直接契約する方法のほかに、Amazon Bedrock、Google Cloud、Microsoft Foundryといった、すでに契約しているクラウド経由で使う方法があります。どれを選ぶかで、請求の窓口、認証、費用の確認方法、監査ログの出どころが変わります。この記事では、Anthropic公式ドキュメント「Enterprise deployment overview」（確認日：2026-11-03）の比較表をもとに、自社の状況から経路を選ぶ判断表を作りました。

30秒で判断
  • 公式ドキュメントは、ほとんどの組織にはClaude for TeamsまたはEnterpriseが最適、と案内している。セットアップが少なく、Web版のClaudeも同じ契約で使える
  • すでにAWS・Google Cloud・Azureで認証・請求・監査を一元管理している会社は、そのクラウド経由（Bedrock・Google Cloud・Foundry）が候補になる
  • クラウド経由ではWeb版のClaudeは含まれない。モデルのバージョン固定など、管理者側の作業も増える

状況別：データの扱いは学習・保持期間の記事、プランの違いはTeam・Enterpriseの選び方へ。

Claude Codeの導入経路には、どんな種類がありますか？

Claude Codeの導入経路とは、モデルの推論を、どの契約・どの基盤で動かすかの選択肢のことです。公式ドキュメント（確認日：2026-11-03）には、次の6種類が並んでいます。

  • Claude for Teams／Enterprise（Anthropicと直接契約）
  • Anthropic Console（API従量課金）
  • Amazon Bedrock
  • Claude Platform on AWS（AWS Marketplace経由の請求）
  • Google CloudのAgent Platform（旧称Vertex AI）
  • Microsoft Foundry

Anthropic Consoleは、公式の比較表で「個人開発者向け」と位置づけられています。そのため、組織での導入は、残りの5つが主な比較対象になります。

クラウド経由で導入するとき、管理者がやることは何ですか？

公式ドキュメント（確認日：2026-11-03）では、クラウド経由（Bedrock・Google Cloud・Foundry・Claude Platform on AWS）で導入する場合のベストプラクティスとして、次の点が挙げられています。

  • モデルのバージョンを固定する：固定しない場合、モデルの別名は、Claude Codeが持つ既定値に解決される。その既定値は最新リリースより遅れることがあり、自社のアカウントでまだ有効になっていないモデルを指す可能性がある。固定すれば、利用者が新しいモデルへ移るタイミングを管理者が決められる。
  • セキュリティ方針を配布する：Claude Codeに許可する操作・許可しない操作を、管理者が設定でき、ローカルの設定で上書きできない。
  • 利用できる経路を制限する：管理対象のPCでは、設定項目「allowedProviders」で使える経路を限定できる（Claude Code v2.1.285以降）。
  • プロキシやゲートウェイを使う場合：全社の利用量の集計、予算の上限、認証の一元化が必要なときは、LLMゲートウェイを前段に置く方法がある。ただし、顧客管理の暗号化キー（CMEK）を使っている場合、ゲートウェイ経由ではClaude Codeの運用テレメトリにCMEKが適用されない、と記載されている。

つまり、クラウド経由は、請求や監査を既存の仕組みに載せられる一方で、モデルの管理や設定の配布を、貴社の管理者が担う範囲が広がります。この運用負担を、費用の見積もりに含めてください。見積もりの項目は「法人導入にかかる費用の内訳」を参照してください。

経路を選ぶときの落とし穴は何ですか？

「クラウド契約があるから」だけで決める

すでにクラウドを契約していても、全員にWeb版のClaudeも使わせたい場合は、クラウド経由ではWeb版が含まれない点が、条件に合わない可能性があります。利用者に何を提供したいかを先に決めてください。

データの扱いの違いを確認しない

経路によって、暗号化の方式やテレメトリの既定値が異なります。たとえば、Bedrock・Google Cloud・Foundry経由では、メトリクス・エラーレポート・/feedbackが既定でオフと記載されています。詳細は「学習・保持期間の記事」にまとめています。

導入後の経路変更を考えない

最初に小さく試す段階と、全社展開の段階で、適した経路が変わることがあります。試行の段階では、手続きの少ない経路で基準を作り、展開の段階で見直す進め方もあります。試行の設計は「PoCの成功基準」を参照してください。

よくある質問

Q. Claude Codeは、Amazon Bedrock経由でも使えますか

使えます。Anthropic公式ドキュメント（確認日：2026-11-03）に、Amazon Bedrock、Google Cloud、Microsoft Foundry、Claude Platform on AWS経由のセットアップ手順が掲載されています。認証はAPIキーまたはAWSの認証情報で、費用はAWS Cost Explorerで確認できます。

Q. TeamsやEnterpriseと、Bedrock経由では何が違いますか

Teams／Enterpriseは、Claude CodeとWeb版のClaudeを1つの契約で使え、SSOと利用状況ダッシュボードが付きます。Bedrock経由は、請求・権限・監査をAWSの仕組みで管理できる一方、Web版のClaudeは含まれません。

Q. 大企業はEnterpriseを選ぶべきですか

一概には言えません。公式ドキュメントでは、Enterpriseはドメイン管理、ロールベースの権限、コンプライアンスAPIが付き、セキュリティ要件が厳しい大規模組織向けと位置づけられています。クラウドで統制を一元化している会社は、クラウド経由が合う場合もあります。

Q. クラウド経由で導入するとき、最初にやることは何ですか

モデルのバージョン固定、セキュリティ方針の配布、利用できる経路の制限の3つを、管理者が決めます。これらは、利用者の手元の設定で上書きされない形で配布するのが前提です。
